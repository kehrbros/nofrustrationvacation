Session summary: road network and routing (2026-10-31)
=====================================================

Summary of the design discussion and implementation so far. The binding details are in Docs/network.md,
Docs/domain.md, Docs/architecture.md and CLAUDE.md.


1. Decisions
------------

- Routing: GraphHopper 11.1 embedded as a library in the backend (module network), no separate service.
  Profile "car" with turn costs and landmarks (LM), no CH, because blocking changes the weighting per request.
  OSRM was considered first and dropped (no per-request blocking, minutes per scenario build).
- Database: PostgreSQL with PostGIS everywhere (stack, local, tests). H2 is removed.
  Tests use Testcontainers via jdbc:tc:postgis:17-3.5-alpine:///vacantagent.
- First region: New Zealand (driving side LEFT, ferries allowed, North and South Island only connect by ferry).
  Test region: central Wellington, backend/src/test/resources/osm/wellington.osm.gz (from Overpass).
- Network model: road_segment = one drivable direction of a GraphHopper edge, junction to junction.
  Replaces the old Road/Segment (there was no real data).
  - Stable surrogate id across refreshes (upsert + soft retire), no copy per version.
  - Business key: osm_way_id + start/end coordinates (1e-7 degrees) + geometry hash.
    GraphHopper does not expose OSM node ids at edges, hence coordinates.
  - Zero-length edges (barriers) get no segment, identical duplicate edges share one segment.
  - Footways, cycleways, paths, steps, bridleways, construction are not imported: roads are only split at road
    junctions, which keeps segments stable. Pedestrian zones stay (some allow cars).
  - edge_mapping: edge_key -> road_segment.id per graph version (n:1), held in memory for routing.
- Spike (branch spike/graphhopper, worktree /home/lukas/vacantagent-spike, throwaway, never merge):
  import is deterministic; about 88 % of keys survive 6 months in central Wellington, so re-planning after a
  refresh is mandatory; strict curbsides fail on one-way roads -> force_curbside=false; pass_through works;
  exact blocking via own WeightingFactory works with LM; map matching found 62/62 edges; Jackson 2 and 3 coexist.
- Modules:
  - network: OSM import, GraphHopper, road_segment/edge_mapping, Routing. Other modules only use network.logic.
  - trips: trips, stops, waypoints, routes, sections. RoutePlanning calls network.Routing without incidents.
  - input (later): raw events, one IncidentSource per feed -> IncidentReport.
  - incidents: incidents, consequences. Later IncidentLocator via SegmentMatching. ConsequenceMatcher joins
    incident_segment and route_section on segment_id plus time window (fractions later).
  - recommendations (later): detours with blocked segments and the same waypoints, leaving later/earlier,
    skipping a waypoint, ranked by arrival and booking deadlines.
  - Scenarios: later, as stored rules sent per request.
- Waypoints belong to a route (between two stops). The user's coordinate is stored, snapping is redone on every
  planning. In a routing request stops are only the first and last point.
- Fractions on route sections say which part of a segment is driven, below 0..1 only on the first and last
  section. They avoid false alarms on long segments once incident_segment has fractions too.
- A route without departure stays unplanned, no time is guessed.
